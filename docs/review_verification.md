# Review improvements and verification — 2026-11-08

This version incorporates the improvements verified below. The original question-comparison snapshots remain historical evidence.

## API output contracts

Questions, hints, feedback and the separate safety classifier use strict JSON schemas generated by Pydantic. Requests require support for the parameters and remain restricted to Anthropic with provider fallback disabled. Local checks still enforce three distinct questions, text limits and safe errors.

An initial strict request failed with HTTP 404. Endpoint metadata identified the legacy temperature parameter as unsupported; removing it allowed the same Anthropic route to accept the strict schema. The client now uses the provider default temperature. This correction does not establish that the temperature requested in historical runs was honored.

## Input safety

The job-title pattern no longer rejects ordinary combinations such as Show / Systems or Print / Key. The full answer, up to 4,000 characters, receives a separate semantic check before feedback generation. The classifier uses the same Claude model and billing route as coaching, with its own instructions and boolean response schema. It is not a separately trained local Prompt Guard model. Each generation or feedback action therefore adds one paid classification call; no automatic retries are used. A failed or rejected classification prevents the coaching request.

Six live classifier samples were checked. This small hand-selected set does not measure general attack resistance, false-positive rates or multilingual coverage.

## Prompt examples and feedback consistency

The selected question prompt combines the original interviewer role with a worked example of the three categories. This is a later revision, not an unchanged winner of the original five-technique comparison.

The feedback prompt includes relevant, insufficient and unrelated answers, equivalent paraphrases and a fixed priority for choosing an improvement. An initial examples-only patch still varied between asking for a concrete example and asking to measure memory use. The final prompt aligns the examples with an explicit priority order.

For a controlled check, the original feedback prompt and the final prompt were each tested twice on two semantically equivalent correct answers and one insufficient answer. Both used the same question, model, strict transport schema, output cap and provider-default temperature. These samples isolate prompt wording rather than comparing different transport formats.

The final four correct-answer outputs all recognized the memory benefit and requested a concrete use example. Both insufficient-answer outputs explained the missing mechanism. This is a limited observation on one question and three answers, not proof of perfectly consistent assessment across roles or questions.

## Scope

The hint prompt targets 8–16 words; the app accepts 8–20 words within one line and 120 characters. Each action has a separate 3-second repeat interval. Provider-side key limits remain necessary for spending control.

Speech transcription, conversational follow-ups, resume input and a framework migration remain future extensions. They are not part of this patch.
